## Design Context

### Users

Linux musicians, sound designers, performance-minded developers, and telemetry explorers using STASH in a terminal. They need to assemble and edit live sonification instruments quickly while understanding which telemetry controls, synth nodes, parameters, and audio-rate routes are connected.

### Brand Personality

Precise, instrumental, and Unix-native. The interface should feel like a dependable live instrument: terse enough for expert use, readable while performing, and quietly instructive when the grammar is unfamiliar.

### Aesthetic Direction

A restrained black-and-white terminal workbench. Neutral chrome, typography, selection, and status treatment keep attention on the patch itself. Color is reserved for semantic identity: repeated occurrences of the same telemetry source or synth node share a stable color, making routes traceable like syntax highlighting. Relationships must remain understandable through labels and structure without relying on color alone.

### Design Principles

1. Color means identity or connection, never decoration or generic status.
2. Keep the public CLI grammar visible; the TUI teaches ordinary STASH clauses rather than introducing a separate graph language.
3. Distinguish control-rate telemetry from audio-rate synth output in wording and structure.
4. Make implicit primary-source routing explicit through contextual explanations.
5. Preserve legibility in monochrome and for color-vision differences with names, arrows, and role labels.
